### Проблема предметной области
Выбор направления подготовки в вузе является сложной задачей многокритериального принятия решений в условиях неопределенности[cite: 1]. Традиционные профориентационные сервисы страдают от фундаментальных недостатков:
1. **Коллаборативная фильтрация** не способна работать с «холодным стартом» (новые абитуриенты не имеют истории оценок)[cite: 1, 3].
2. **Экспертные опросники (типа теста Климова)** дают грубую типизацию и не привязаны к реальным учебным планам конкретного университета[cite: 1, 3].
3. **Категориальный поиск по тегам** страдает от проблемы лексического разрыва (vocabulary mismatch problem): абитуриент и преподаватель используют разную терминологию, а совпадение слов оценивается бинарно (0 или 1), не отражая глубины погружения в предмет[cite: 1, 3].
4. **Внедрение новой модели «образовательных ядер» в ПНИПУ:** университет переходит на двухуровневую организацию образовательных программ («Образовательное ядро» $\to$ «Направление подготовки»)[cite: 1, 86, 92]. Существующие инструменты не позволяют ранжировать образовательные траектории на разных уровнях иерархии[cite: 1, 3].

### Предлагаемое решение и научная новизна
В системе реализован гибридный контентно-ориентированный подход[cite: 1, 3]:
1. Направление подготовки формализуется как **нечеткое множество предметных доменов**, где степень принадлежности $\mu \in [0; 1]$ вычисляется на основе семантических эмбеддингов вариативной части учебного плана[cite: 1, 3].
2. Внедрена концепция **иерархического семантического сжатия информации**: предметные интересы не задаются жестким внешним словарем, а автоматически извлекаются из официальных аннотаций дисциплин кафедры и группируются алгоритмом агломеративной кластеризации (HAC) в три масштаба выбора: **1 концепт** (макро-уровень ядра), **3 концепта** (мезо-уровень специализации) и **5 концептов** (микро-уровень технологий).
3. Используется двухэтапный конвейер: **строгая фильтрация** по формальным академическим ограничениям (ЕГЭ, форма обучения, бюджет/контракт, филиал) и **нечеткое семантическое ранжирование** методом взвешенных сумм (WSM) с весами ROC (Rank Order Centroid)[cite: 1, 3].
4. Косинусные оценки калибруются с помощью **процентильного преобразования (Percentile Rank)**, что устраняет анизотропию векторного пространства и делает рекомендации прозрачно интерпретируемыми для абитуриента[cite: 1, 3].
5. Реализована **подсистема администрирования и управления жизненным циклом семантических профилей**: поддержка ручного и автоматического (по таймеру) пересчета эмбеддингов и словарей интересов в изолированном процессе с ведением детального журнала выполнения.

### Ключевые архитектурные решения:
* **Неблокирующее обновление данных:** При ручном запуске обновления администратором или срабатывании таймера `APScheduler` тяжелая нейросетевая обработка запускается в отдельном дочернем процессе ОС. По завершении процесса память (2–4 Гб RAM/VRAM, занимаемые моделью FRIDA) полностью освобождается[cite: 3].
* **Защита от состояния гонки (Race Condition):** Таблица `pipeline_runs` выступает в роли распределенной блокировки (Mutex). Если обновление уже запущено по таймеру, повторный ручной запуск блокируется до завершения текущего цикла.
* **Высокая пропускная способность (5000+ пользователей):** Онлайн-контур работает исключительно с предрассчитанными коэффициентами принадлежности $\mu$, выполняя запросы за единицы миллисекунд[cite: 1, 2].

## 3. Математический аппарат системы

### 3.1. Представление образовательной программы
Вариативная часть направления подготовки $D$ состоит из $N_D$ профильных дисциплин: $V_D = \{d_1, d_2, \dots, d_{N_D}\}$[cite: 1, 3]. Интегральный вектор направления формируется усреднением нормализованных эмбеддингов дисциплин[cite: 1, 3]:
$$V_D = \frac{1}{N_D} \sum_{i=1}^{N_D} \text{FRIDA}(d_i), \quad V_D \in \mathbb{R}^{1536}, \quad \Vert{}V_D\Vert{} = 1$$

### 3.2. Функция принадлежности предметного домена к направлению
Степень семантического родства предметного домена (интереса) $\text{domain}$ и направления $D$ рассчитывается через косинусное сходство их векторов[cite: 1, 3]:
$$\mu_D(\text{domain}) = \cos(V_{\text{domain}}, V_D) = \frac{V_{\text{domain}} \cdot V_D}{\Vert{}V_{\text{domain}}\Vert{} \Vert{}V_D\Vert{}}, \quad \mu_D \in [0; 1]$$

### 3.3. Иерархическое сжатие информации (HAC)
Множество извлеченных терминов направления $K_D$ векторизуется моделью FRIDA[cite: 3]. Расстояние между терминами определяется как $d_{\cos}(u, v) = 1 - \cos(u, v)$. Объединение кластеров выполняется по методу среднего связывания (Average Linkage):
$$D(A, B) = \frac{1}{\vert{}A\vert{} \cdot \vert{}B\vert{}} \sum_{u \in A} \sum_{v \in B} d_{\cos}(u, v)$$
Дендрограмма рассекается на фиксированных уровнях:
* $k = 5$ — микро-уровень детальных технологий;
* $k = 3$ — мезо-уровень профилей подготовки;
* $k = 1$ — макро-уровень образовательного ядра/кафедры.

Вектор интереса $V_{\text{domain}}$ рассчитывается как центроид векторов терминов, вошедших в соответствующий кластер:
$$V_{\text{domain}} = \frac{1}{\vert{}S\vert{}} \sum_{v \in S} v, \quad \Vert{}V_{\text{domain}}\Vert{} = 1$$

### 3.4. Расчет весов приоритетов абитуриента методом ROC (Rank Order Centroid)
Абитуриент упорядочивает $k$ выбранных интересов по степени важности ($3 \le k \le 5$)[cite: 1, 3]. Вес $W_i$ для интереса с рангом $i$ рассчитывается аналитически[cite: 1, 3]:
$$W_i = \frac{1}{k} \sum_{j=i}^k \frac{1}{j}, \quad \sum_{i=1}^k W_i = 1$$

### 3.5. Интегральная оценка соответствия методом WSM (Weighted Sum Model)
Оценка направления подготовки $D$ вычисляется как взвешенная сумма степеней принадлежности[cite: 1, 3]:
$$\text{Score}_D = \sum_{i=1}^k W_i \cdot \mu_D(\text{domain}_i), \quad \text{Score}_D \in [0; 1]$$

### 3.6. Процентильный ранг и агрегация по образовательным ядрам
Для устранения неравномерности распределения косинусных мер оценка преобразуется в процентильный ранг[cite: 1, 3]:
$$PR(D_i) = \frac{L_i + 0.5 \cdot E_i}{N} \cdot 100\%$$
где $L_i$ — количество направлений выборки с меньшим Score, $E_i$ — с равным Score, $N$ — общее количество направлений[cite: 1, 3].

Итоговая оценка образовательного ядра $C_k$ рассчитывается как среднее значение процентильных рангов его лучших $K$ направлений (Top-K, по умолчанию $K=5$)[cite: 1, 3]:
$$\text{Score}_{C_k} = \frac{1}{K} \sum_{D \in \text{TopK}(C_k)} PR(D)$$

## 5. Спецификация основных эндпоинтов REST API

### Клиентский контур (для абитуриентов):
* `GET /api/v1/meta/filters` — получение справочников (предметы ЕГЭ, филиалы, формы обучения)[cite: 1, 2].
* `GET /api/v1/domains?level={1|3|5}` — получение списка областей интересов для выбранного уровня семантического сжатия.
* `POST /api/v1/recommend` — строгая фильтрация и расчет иерархической рекомендации («Ядро $\to$ Направления»)[cite: 1, 3].

### Административный контур (управление обновлениями и журнал):
* `POST /api/v1/admin/pipeline/run` — ручной запуск процесса обновления содержания направлений и пересчета эмбеддингов.
* `GET /api/v1/admin/pipeline/runs` — получение истории (журнала) всех выполненных и текущих обновлений со статистикой.
* `GET /api/v1/admin/pipeline/runs/{run_id}` — получение подробного пошагового лога конкретного запуска.
* `GET /api/v1/admin/pipeline/schedule` — получение текущих настроек таймера автоматического обновления.
* `PUT /api/v1/admin/pipeline/schedule` — изменение расписания таймера (включение/выключение, настройка интервала/cron).

## 6. Технологический стек

* **СУБД:** PostgreSQL 16 с расширением `pgvector` (индексация HNSW)[cite: 1].
* **Backend:** Python 3.11, FastAPI, SQLAlchemy 2.0 (asyncio), Asyncpg, Pydantic V2, Alembic, APScheduler.
* **NLP & Data Science:** Hugging Face / Sentence-Transformers (модель FRIDA, размерность эмбеддинга 1536)[cite: 3], spaCy (`ru_core_news_lg`), PyMorphy3, SciPy (модуль `cluster.hierarchy`), Scikit-learn.
* **Frontend:** Vue 3 (Composition API, `<script setup lang="ts">`), TypeScript, Vite, Pinia, Vue Router, Axios.
* **Инфраструктура:** Docker, Docker Compose, Nginx.

### Проблема предметной области
Выбор направления подготовки в вузе является сложной задачей многокритериального принятия решений в условиях неопределенности. Традиционные профориентационные сервисы страдают от фундаментальных недостатков:
1. **Коллаборативная фильтрация** не способна работать с «холодным стартом» (новые абитуриенты не имеют предыстории оценок).
2. **Экспертные опросники (типа теста Климова)** дают грубую типизацию и не привязаны к реальным учебным планам конкретного университета.
3. **Категориальный поиск по тегам** страдает от проблемы лексического разрыва (vocabulary mismatch problem): абитуриент и профессор используют разную терминологию, а совпадение слов оценивается бинарно (0 или 1), не отражая глубины погружения в предмет.
4. **Внедрение новой модели «образовательных ядер» в ПНИПУ:** университет переходит на двухуровневую организацию образовательных программ («Образовательное ядро» $\to$ «Направление подготовки»). Существующие инструменты не позволяют ранжировать образовательные траектории на разных уровнях иерархии.

### Предлагаемое решение и научная новизна
В системе реализован гибридный контентно-ориентированный подход:
1. Направление подготовки формализуется как **нечеткое множество предметных доменов**, где степень принадлежности $\mu \in [0; 1]$ вычисляется на основе семантических эмбеддингов вариативной части учебного плана.
2. Внедрена концепция **иерархического семантического сжатия информации**: предметные интересы не задаются жестким внешним словарем, а автоматически извлекаются из официальных аннотаций дисциплин кафедры и группируются алгоритмом агломеративной кластеризации (HAC) в три масштаба выбора: **1 концепт** (макро-уровень ядра), **3 концепта** (мезо-уровень специализации) и **5 концептов** (микро-уровень технологий).
3. Используется двухэтапный консилиум: **строгая фильтрация** по формальным академическим ограничениям (ЕГЭ, форма обучения, бюджет/контракт, филиал) и **нечеткое семантическое ранжирование** методом взвешенных сумм (WSM) с весами ROC (Rank Order Centroid).
4. Косинусные оценки калибруются с помощью **процентильного преобразования (Percentile Rank)**, что устраняет анизотропию векторного пространства и делает рекомендации прозрачно интерпретируемыми для абитуриента.

### Преимущества разделения контуров:
* **Производительность:** Онлайн-сервер FastAPI **не загружает** модель FRIDA в оперативную память. Сервер выполняет только реляционную фильтрацию и простые арифметические операции над уже предрассчитанными коэффициентами $\mu$, что позволяет обслуживать более 5000 одновременных пользователей без задержек.
* **Масштабируемость:** База данных хранит векторы в формате `VECTOR(1536)` расширения `pgvector`, что обеспечивает возможность динамического поиска по косинусному расстоянию при необходимости.

## 3. Математический аппарат системы

### 3.1. Представление образовательной программы
Вариативная часть направления подготовки $D$ состоит из $N_D$ профильных дисциплин: $V_D = \{d_1, d_2, \dots, d_{N_D}\}$. Интегральный вектор направления формируется усреднением нормализованных эмбеддингов дисциплин:
$$V_D = \frac{1}{N_D} \sum_{i=1}^{N_D} \text{FRIDA}(d_i), \quad V_D \in \mathbb{R}^{1536}, \quad \Vert{}V_D\Vert{} = 1$$

### 3.2. Функция принадлежности предметного домена к направлению
Степень семантического родства предметного домена (интереса) $\text{domain}$ и направления $D$ рассчитывается через косинусное сходство их векторов:
$$\mu_D(\text{domain}) = \cos(V_{\text{domain}}, V_D) = \frac{V_{\text{domain}} \cdot V_D}{\Vert{}V_{\text{domain}}\Vert{} \Vert{}V_D\Vert{}}, \quad \mu_D \in [0; 1]$$

### 3.3. Иерархическое сжатие информации (HAC)
Множество извлеченных терминов направления $K_D$ векторизуется моделью FRIDA. Расстояние между терминами определяется как $d_{\cos}(u, v) = 1 - \cos(u, v)$. Объединение кластеров выполняется по методу среднего связывания (Average Linkage):
$$D(A, B) = \frac{1}{\vert{}A\vert{} \cdot \vert{}B\vert{}} \sum_{u \in A} \sum_{v \in B} d_{\cos}(u, v)$$
Дендрограмма рассекается на фиксированных уровнях:
* $k = 5$ — микро-уровень детальных технологий;
* $k = 3$ — мезо-уровень профилей подготовки;
* $k = 1$ — макро-уровень образовательного ядра/кафедры.

Вектор интереса $V_{\text{domain}}$ рассчитывается как центроид векторов терминов, вошедших в соответствующий кластер:
$$V_{\text{domain}} = \frac{1}{\vert{}S\vert{}} \sum_{v \in S} v, \quad \Vert{}V_{\text{domain}}\Vert{} = 1$$

### 3.4. Расчет весов приоритетов абитуриента методом ROC (Rank Order Centroid)
Абитуриент упорядочивает $k$ выбранных интересов по степени важности ($3 \le k \le 5$). Вес $W_i$ для интереса с рангом $i$ рассчитывается аналитически:
$$W_i = \frac{1}{k} \sum_{j=i}^k \frac{1}{j}, \quad \sum_{i=1}^k W_i = 1$$

### 3.5. Интегральная оценка соответствия методом WSM (Weighted Sum Model)
Оценка направления подготовки $D$ вычисляется как взвешенная сумма степеней принадлежности:
$$\text{Score}_D = \sum_{i=1}^k W_i \cdot \mu_D(\text{domain}_i), \quad \text{Score}_D \in [0; 1]$$

### 3.6. Процентильный ранг и агрегация по образовательным ядрам
Для устранения анизотропии и неравномерности распределения косинусных мер оценка преобразуется в процентильный ранг:
$$PR(D_i) = \frac{L_i + 0.5 \cdot E_i}{N} \cdot 100\%$$
где $L_i$ — количество направлений выборки с меньшим Score, $E_i$ — с равным Score, $N$ — общее количество направлений.

Итоговая оценка образовательного ядра $C_k$ рассчитывается как среднее значение процентильных рангов его лучших $K$ направлений (Top-K, по умолчанию $K=5$):
$$\text{Score}_{C_k} = \frac{1}{K} \sum_{D \in \text{TopK}(C_k)} PR(D)$$

## 4. Схема реляционной базы данных (PostgreSQL + pgvector)

Схема нормализована до 3NF и состоит из трех логических блоков:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. АКАДЕМИЧЕСКИЙ БЛОК (Семантика и учебные планы)                           │
│    • direction_cores          (id, name)                                    │
│    • faculties                (id, name)                                    │
│    • study_directions         (id, code, name, faculty_id, core_id,         │
│                                embedding: VECTOR(1536))                     │
│    • disciplines              (id, direction_id, name, annotation_text,     │
│                                embedding: VECTOR(1536))                     │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. БЛОК СЕМАНТИЧЕСКИХ ИНТЕРЕСОВ (Сжатие 1-3-5)                              │
│    • domains                  (id, name, compression_level: [1,3,5],        │
│                                embedding: VECTOR(1536))                     │
│    • direction_domain_affiliations (id, direction_id, domain_id,            │
│                                     membership_degree: FLOAT)               │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. БЛОК КОНКУРСА И ФИЛЬТРАЦИИ (Правила приема ПНИПУ)                        │
│    • campuses                 (id, name)                                    │
│    • exam_subjects            (id, name)                                    │
│    • admission_conditions     (id, direction_id, campus_id, study_form,     │
│                                funding_type, is_foreign_available,          │
│                                passing_score_prev_year, budget_places)      │
│    • admission_exam_requirements (id, condition_id, exam_id, min_score)     │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 5. Технологический стек

* **СУБД:** PostgreSQL 16 с расширением `pgvector` (индексация HNSW).
* **Backend:** Python 3.11, FastAPI, SQLAlchemy 2.0 (asyncio), Asyncpg, Pydantic V2, Alembic.
* **NLP & Data Science:** Hugging Face / Sentence-Transformers (модель FRIDA, размерность эмбеддинга 1536), spaCy (`ru_core_news_lg`), PyMorphy3, SciPy (модуль `cluster.hierarchy`), Scikit-learn.
* **Frontend:** Vue 3 (Composition API, `<script setup lang="ts">`), TypeScript, Vite, Pinia, Axios.
* **Инфраструктура:** Docker, Docker Compose, Nginx.
